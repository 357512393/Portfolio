# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.
After each completed adjustment, include the local preview URL in the user-facing response.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

- The page background is pure black; do not change the overall reference-site structure without explicit user approval.
- All interface copy is Chinese. Except for the upper-left brand, interface typography stays fixed at the reference site's 13px desktop size; auxiliary copy may use 12px.
- The upper-left brand reads `辜锟泓`. The desktop intro is positioned in the upper-right region at `top: 16.5%` and `left: 70.6%`, and reads `厦门` plus the approved two-line product/AI experience statement.
- The homepage project index contains eight entries in this exact order: `2026 Portfolio`, `知识付费直播项目`, `PC直播助手`, `AI设计工作流`, `AI应用集合`, `AI官网设计`, `留学酱`, `其他设计`.
- Every left homepage project-index item has a fixed `22px` height and `22px` line height. The complete eight-item index is vertically centered in the viewport on desktop, short screens, and mobile.
- Hovering or keyboard-focusing a left homepage project item shifts only its text `5px` to the right over `180ms cubic-bezier(0.22, 1, 0.36, 1)`; the text restores on exit and the button hit area never moves. Reduced-motion preferences are respected.
- The lower-left prompt reads `/ 上下滑动`. The project action reads `/ 点击查看` normally, changes to `\ 点击查看` on hover or keyboard focus, uses a pointer cursor, and opens the active project image.
- Every slash-bearing control follows the supplied motion-video reference without clipping, duplicate layers, or vertical movement. The slash and text share the same baseline and inherited line height, so `/` and its flipped `\` state remain vertically aligned with the copy. On hover/focus the `/` glyph flips horizontally in place into `\` over `160ms cubic-bezier(0.22, 1, 0.36, 1)`, then the text shifts 5px to the right over 180ms with a 20ms delay. Both return to rest when the pointer/focus leaves. This applies to the three upper-right navigation links, the project action, and the lower-left prompt; reduced-motion preferences are respected.
- The about page keeps its own `/ 项目`, `/ 摄影`, `/ 关于` navigation. When it enters, the first frame disables slash/text transitions and the underlying homepage navigation is hidden from pointer events, preventing a duplicate-hover jump while preserving the about-page controls. Do not force a `24px` height or line height.
- The about page uses the supplied black grid hero with `KUN / HONG` at lower left, and a right-side Velora-style About Me experience list. Experience rows use Velora's content, typography scale, arrow/underline hover treatment, and single-open expand/collapse motion; do not restore the removed hero copy or scroll cue.
- About-page content follows the selected kynejang.com reference only for the body layout: a desktop left identity/contact column and right experience column divided by a fine vertical line, stacking vertically on mobile. Do not copy that reference's logo or top navigation. Use the supplied identity, WeChat contact, QR image, and work-history copy from the user's second screenshot.
- The about identity column starts directly with `辜锟泓` and `UI/UX体验设计师`; do not show a `[ 我是谁 ]` eyebrow or reserve vertical space for it.
- The about page does not show a separate standalone `关于` label in the upper-left; the page state is represented by the active `/ 关于` item in the upper-right navigation.
- The about-page navigation keeps the homepage's exact fixed position (`top: var(--edge-y)`, `right: var(--edge-x)`); body layout changes must not move it.
- When leaving the about page through its navigation, the underlying homepage navigation locks slash/text transitions until the pointer leaves its region, preventing a hover animation from retriggering as the two page layers switch. The homepage hover motion resumes on the next pointer entry.
- During that transition lock, homepage navigation hover/focus color, slash flip, and text translation are all suppressed; the pointer handoff must be visually static rather than an instantaneous reset.
- The transition lock must land on the destination link's final hover state without animation: `\\` slash, `5px` text translation, and white label. It must not reset the destination to the resting `/` state while the pointer remains over it.
- The desktop layout scales fluidly with browser width and height from a minimum supported viewport width of 1280px. The mobile branch is supported at 809px and below; intermediate tablet widths from 810px to 1279px are outside the supported layout range.
- The homepage Canvas uses `min(devicePixelRatio, 2)` by default. If either real Canvas dimension would exceed `4096px`, its DPR is reduced to `1.5` or lower when needed to keep the dimension within that GPU limit; this is recalculated on resize.
- The archived 19:19 mobile composition remains a separate branch at 809px and below: 30px upper-left brand, 13px navigation/index/number/toggle, no intro/detail/type/thumbnail rail, and a fixed 176px internal poster base. Desktop sizing and anchoring changes must not affect this branch.
- The photography tertiary viewer follows the Gregor Collienne Focus gallery structure while retaining this portfolio's black background and upper-right navigation: a finite, vertically scrollable 30-image thumbnail rail sits on the left, thumbnails preserve each source image's natural portrait or landscape ratio at an 80px desktop width, and their horizontal position forms a smooth rightward curve around the viewport center while scrolling. The selected image remains centered at its natural ratio with an approximately 82vh height ceiling and must never exceed one viewport.
- The tertiary viewer's thumbnail curve uses the reference site's exact desktop motion parameters: a `280px` center influence radius, a quadratic `64px` maximum horizontal offset, and per-frame `0.08` interpolation. Wheel input snaps the nearest thumbnail to the viewport center after `140ms` without input; mouse/touch drag snaps immediately on release, and the centered thumbnail becomes the large selected image.
- The tertiary thumbnail rail mirrors the reference site's two-stage smoothing: its displayed vertical scroll position follows an independent wheel/drag target with `0.03` interpolation per 60Hz frame, while the curve continues to follow with `0.08`. Snapping updates the same target instead of invoking native smooth scrolling, so input, inertial travel, curve deformation, and centering never compete for `scrollTop`.
- Once a tertiary thumbnail snap begins, vertical interpolation increases to `0.12` until centered; this is the approved extension to the reference motion so the requested automatic snap finishes promptly after the `140ms` wheel-stop delay while remaining eased.
- Changing the centered/selected tertiary photo must not recreate the thumbnail-rail animation effect. Its scroll target, displayed position, and per-thumbnail curve interpolation cache persist for the full open-detail lifecycle so the rail cannot twitch when snapping finishes and the large image updates.
- Tertiary large images use the reference Focus gallery's seamless switching structure: all 30 focus items stay pre-mounted and absolutely stacked for the full detail lifecycle, inactive items have `opacity: 0`, and the active item switches directly to `opacity: 1` with no fade or remount. Do not reintroduce keyed single-image mounting or GSAP entrance animation between selected photos.
